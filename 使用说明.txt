TikTok通知采集 V1.0 正式版（2026-11-03）

文件说明
- TikTok通知采集/：Chrome Manifest V3 扩展（manifest 声明版本 1.0.0）
- AppsScript接收端_V1.0.gs：Google Apps Script 接收端（写入逻辑沿用 v8，时区改为仅在插件控制）
- TikTok通知采集/SECURITY_REVIEW.md：历次安全审查记录（保留原始历史描述）

一、安装 Chrome 扩展
1. 备份旧版插件配置（尤其是接收地址、Token 和目标表格链接）。
2. 解压 ZIP；在 Chrome 地址栏打开 chrome://extensions，开启“开发者模式”。
3. 建议在原有扩展文件夹的相同目录覆盖更新，再在 chrome://extensions 点击“重新加载”，以尽可能保留原扩展 ID 及原有设置。
4. 若改为“加载已解压的扩展程序”且 Chrome 将其视作新的扩展，旧设置/去重记录可能无法自动迁移；不要同时启用两份插件，以免重复采集。
5. 插件弹窗设置 Apps Script /exec 接收地址、与脚本一致的 Token、目标表格链接（带 gid）及账号。

二、Apps Script 接收端部署
1. 打开原 Apps Script 项目，将 AppsScript接收端_V1.0.gs 全文替换旧接收端代码。
2. 修改 const TOKEN = 'REPLACE_WITH_YOUR_TOKEN' 为实际口令（插件内输入同一口令）。不要将真实口令公开。
3. “部署”→“管理部署”→编辑原部署→版本选“新版本”→“部署”。更新现有部署时通常保留原 /exec 地址。
4. 之前用户明确要求暂缓修改默认表格 ID，因此接收端 DEFAULT_SPREADSHEET_ID 暂时仍是原值。插件指定的目标表格优先。
5. 未在此版本实现 Google Apps Script 服务端去重：网络超时后重发等情况仍有重复入库可能。

三、时区设置（只在插件中设置）
- 插件弹窗中设置写入时区，默认 Asia/Ho_Chi_Minh（越南 UTC+7）。
- 插件生成 displayCapturedAt 字符串（yyyy-MM-dd HH:mm:ss），接收端只写入该字符串。
- Apps Script 代码不再设置时区，也不执行时区转换；不需要查看或修改 Apps Script 项目时区。
- 更改插件时区仅影响新采集记录。已入库数据不会自动转换，旧补发队列按原采集时保留的时区转换。
- 如果旧发送端没有 displayCapturedAt，接收端会原样写入其 UTC 时间戳；因此必须同时更新插件和接收端。

四、写入位置
- 账号目标工作表、评论收集、诊断快照：每批新数据从第 3 行插入，原第 3 行及以下的记录整体下移。
- 第 1 行表头、第 2 行保持不变。接收端使用脚本锁避免批次交叉插入。

五、功能保留
- 自动（约 2 小时，页面空闲时）/手动/暂停采集。
- TikTok 页面采集悬浮框及×隐藏；弹窗中可重新显示。隐藏不等于暂停采集。
- Token 显示/隐藏切换，账号优先手动输入，评论双写，失败补发，插件本地有限去重。

六、使用前验证
- 在测试 TikTok 账号与测试 Google 表格中检查：时间、账号、gid、第三行插入、评论双写、手动/自动、隐藏恢复与失败补发。
- 本包已进行本地语法/静态核对；尚未在用户真实 TikTok 和 Google 环境端到端联调。

安全提示
- 你此前在对话中粘贴过实际格式的 Token，建议更换成随机长口令，同时修改 Apps Script 和插件。
- 诊断模式可能包含页面 HTML 快照，非排错期间建议关闭。
- 不要公开 Apps Script 的真实 Token。请避免在表格和源码公开存储敏感信息。
